# Durable security monitor state

The monitor library stores observations and event history. It does not run a scheduler, deliver notifications, resolve dependencies, install packages, or authorize a later transport request. The CLI/MCP adapter must obtain current operator authorization for each operation.

Registration is configuration only. `MonitorStore::register` assigns random immutable monitor and epoch IDs without inspecting a project or executing Python. Names are labels and may be reused. The declared comparison domain contains the approved project/environment, backend, inventory scope, provider/source/index policy identities, and observation schema. The runtime identity is learned by the first explicit fresh check, within the initial epoch. A later interpreter/tag/marker profile or configuration change starts a new epoch before the replacement baseline is written. Package versions, inventory IDs, package instance IDs, and ordinary project/lock file changes do not define the comparison domain.

`prepare_check` returns an in-process ticket containing the expected configuration revision and snapshot generation. Its `assessment_options(current_inventory)` maps stored versionless package identities to current exact instance IDs for previous-candidate revalidation. `known_advisories()` supplies stored provider/record IDs for bounded direct rehydration; these are evidence locators, not permission to disclose a package or contact an endpoint. The adapter must validate the current provider, source, authentication scope, mapping, target, and disclosure grants before HTTP. An invalidated assessment traversal cursor restarts assessment traversal; it does not reset the monitor epoch.

`commit_check` receives the untruncated `SecurityAssessment`, a trusted `CheckContext`, and an optional replay cursor. The context explicitly states online/offline mode, inventory freshness, observation time, and an absolute deadline. Empty offline inventories cannot prove removal. A short root-level OS lock protects registry revision/generation validation and the commit. Concurrent tickets for the same generation cannot overwrite each other. Assessment work happens outside the store lock; a stale ticket must be reassessed or retried against a fresh ticket.

The snapshot is the commit unit: baseline, lineage graph, current findings, event history, assessment continuation, and monotonic sequence counters are written together. A private sibling temporary file is synchronized, renamed, and followed by directory synchronization. Failure before replacement is `NotCommitted`; failure after replacement, including directory synchronization failure, is `Indeterminate`. Retry the same in-process ticket or reload/replay: committed IDs remain unchanged. A lost response does not roll back an event.

The registry records configuration changes before a replacement baseline. While a new epoch awaits its baseline, reads return `E_MONITOR_BASELINE_REQUIRED` with a new-epoch empty summary. An old-epoch cursor returns `E_MONITOR_CURSOR_SCOPE` with the same new-scope summary. The previous snapshot remains available internally for recovery but its findings, evidence, paths, and IDs are not exposed under the new configuration.

Findings follow persisted versionless package/source/authentication/mapping/scope identities. Alias additions preserve IDs; merges retain an earlier persisted lineage and link absorbed lineages; splits recover prior lineages or allocate linked children. Merge/split corrections are evidence changes, not fabricated new advisories or resolutions. Same-version disappearance from a provider query does not resolve a known finding. Fresh complete relevant evidence after a version upgrade can resolve it, and a fresh complete inventory removal can resolve it independently of provider outages. Explicit withdrawal requires direct fresh correction evidence. Severity uses conservative provider labels from the assessment engine; unknown is not ranked below low, and the last known authoritative severity survives an unknown interval.

Each authoritative transition uses its own required evidence. A fresh public positive can coexist with unrelated private-source failures. Offline/stale evidence can retain known positives but cannot emit authoritative fix/removal/withdrawal/severity transitions. Incomplete episodes coalesce by source, reason, and coverage rather than timestamps or prose. Raw hashes and fetch times remain evidence; prose/timestamp changes do not by themselves create incidents.

Replay is non-consuming. Cursors are opaque traversal positions and confer no authority. Each page returns at most 100 events strictly after the requested cursor and advances only to its last returned event. Origin sequence zero refers to the current epoch. Scope, high-water, and expiry errors include the current summary and low-water/resynchronization information. Retention is at most 1,000 events and 90 days; active baselines and sequence counters survive history pruning. Newly committed event metadata is separate from replay pagination and reports truncation/gaps.

`MonitorStore::create_from_parent(options, parent_path, parent_handle)` creates a strict relative suffix from an already approved held directory. The CLI/MCP adapter uses its current grant’s held parent; it must not reopen a pathname as a substitute authority. The final walked directory remains held through lock-file initialization. Directory and file creation recheck the absolute deadline immediately before mutation.

The default state directory is outside the project repository under the user's platform state/data directory. The current filesystem profile supports Unix private directories (0700), private regular files (0600), pinned directory handles, no-follow/nonblocking file opens, root/lock inode checks, and process locks. Read-only opening and replay do not create registrations or silently repair corrupt data. Unknown persisted schema versions are errors. Recovery requires a separate explicit operator-authorized action; registration names cannot recover a deleted registry identity.

Limits reject rather than trim: 100 monitors and 1,000 inventory instances, plus bounded checkpoint sizes. Narrower limits and absolute deadlines cannot widen authority. State contains credential-free identities and selected evidence, not raw credentials or reusable authorization tokens.
